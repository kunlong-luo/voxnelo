# Moonshine 0.0.65 cross-platform dependency and rights evidence (2026-11-22)

**Decision: PARTIAL EVIDENCE — NOT LEGALLY APPROVED; v1.0.4 MUST REMAIN UNPUBLISHED.** This is a dated, evidence-backed snapshot of upstream **source declarations** and metadata extracted from actual CI-installed Python environments. It does not approve model redistribution, any native linked binary, installer publishing or real-microphone acceptance.

## Immutable upstream SDK source and declared dependencies

- Official Moonshine source [tag `v0.0.65`](https://github.com/moonshine-ai/moonshine/tree/v0.0.65) resolves to immutable source commit **`c09053306769543292b676c0c1e6bd55b2b6ca38`** (checked via upstream GitHub API). This is a *source-code revision*, not proof the published PyPI Wheels were reproducibly built from it.
- Its [`python/pyproject.toml`](https://github.com/moonshine-ai/moonshine/blob/v0.0.65/python/pyproject.toml) and [`python/setup.py`](https://github.com/moonshine-ai/moonshine/blob/v0.0.65/python/setup.py) declare six **unversioned** direct Python dependencies: `numpy`, `sounddevice`, `requests`, `tqdm`, `filelock`, `platformdirs`; `setup.py` declares `license_files=("LICENSE",)`. The SDK package version is fixed but these dependencies are not locked by `moonshine-voice==0.0.65` alone.
- The versioned source [`LICENSE`](https://github.com/moonshine-ai/moonshine/blob/v0.0.65/LICENSE) states MIT for code other than `core/third-party` and English-language models; specified non-English models are separately noncommercial. **This statement does not establish third-party binary or transitive dependency rights.**
- The **v0.0.65** source's [`python/src/moonshine_voice/download.py`](https://github.com/moonshine-ai/moonshine/blob/v0.0.65/python/src/moonshine_voice/download.py) chooses `https://download.moonshine.ai/model/medium-streaming-en/quantized` for default English Medium Streaming and declares precisely: `adapter.ort`, `cross_kv.ort`, `decoder_kv.ort`, `encoder.ort`, `frontend.ort`, `streaming_config.json`, `tokenizer.bin`, `decoder_kv_with_attention.ort`. This grounds model **file names and endpoint** in versioned source, *not* a signed/revision-pinned byte inventory. Voxnelo separately checks eight pinned SHA-256 digests after download.
- On an attempt to load official `moonshine-ai/moonshine-voice-assets` `v0.0.65/FILES.tsv`, the endpoint reported `Invalid rev id: v0.0.65` on this review date. Current `main/FILES.tsv` had legacy `model/medium-streaming-en/quantized/` paths but supplies md5/CRC32C rather than independent SHA-256 attestations. Thus the **eight Voxnelo model SHA-256 values still have not been matched to an immutable official asset snapshot**; do not assert that they have. This is a record of a lookup failure, not proof a permanent asset tag never existed.

**Confirmed reproducibility issue:** the native matrix selects `python-version: '3.12'` in `actions/setup-python`, but the Windows installer currently tries `py -3` before `python`. This chose **Python 3.15.2** on the Windows runner despite the workflow's 3.12 setup. It passed this native build but is **not** a repeatable pinned Python interpreter contract. Track a focused installer/CI version-selection fix without changing a production requirement or falsely labeling untested Python versions as accepted.

Observed license/NOTICE metadata relevant to further inspection:

- `moonshine-voice==0.0.65` exposes one installed LICENSE; native library filenames include `moonshine.dll` and `onnxruntime.dll` on Windows, and `libmoonshine` and `libonnxruntime` variants on Unix hosts. These observations alone cannot establish that the runtime binaries were built from the tagged source and with only the above third-party code.
- `numpy==2.5.5` declares a **compound** license expression (`BSD-3-Clause AND 0BSD AND MIT AND Zlib AND CC0-1.0`) and exposes **20** installed license/notice-file entries per OS, in addition to native compiled libraries including OpenBLAS. Review those individual obligations; **do not collapse them to just BSD**.
- `sounddevice==0.5.6` exposes a LICENSE and the Windows/macOS package inventories list seven platform-named PortAudio binaries. Investigate which binaries are shipped/loaded and their notices on each OS.
- Some packages have a legacy `License` field rather than an SPDX expression. The generated `manualReviewRequired: []` means only that each package has **some** license declaration or notice file. It **never** means the rights were independently verified or are commercially suitable.

Obtain original **three** v0.0.65 PyPI Wheels by immutable filename; independently verify registry SHA-256; examine embedded LICENSE / METADATA / `*.dll` / `*.so` / `*.dylib`, dynamic links and notice requirements against the actual package. The installed metadata collector is supplemental, not a full binary scan.
2. Lock every relevant **transitive Python package version and platform Wheel hash** (not just Moonshine's SDK), select a documented supported Python runtime for each platform, and re-run actual native installer validation. Current versions are an observational snapshot, not an immutable requirements lock.
3. Associate Voxnelo's eight quantized model-file SHA-256 hashes with an **immutable official model asset revision** and record any redistribution, attribution and CDN terms before approving public release.
4. Review the actual packaged Electron/npm production dependency/NOTICE inventory separately, and obtain the real direct-human microphone tests required by [the evidence ledger](../release/V1.0.4-PHYSICAL-DEVICE-EVIDENCE.md).
5. **No automatic legal approval**: an explicit named reviewer must record individual decisions, date and evidence per final artifact. Keep v1.0.4 Draft unpublished until all mandatory gates pass. Never upload personal audio or identifiable transcripts.

## 2026-11-23 version-pin and interpreter follow-up (CI review required)

The subsequent candidate installer now **prefers and requires 64-bit Python 3.12 on Windows for a new opt-in installation**, trying `py -3.12` and then a `python` executable that explicitly proves Python 3.12/x64. This removes the previous unrestricted `py -3` selection that actually chose Python 3.15.2 in Windows CI. Already installed user runtimes are not silently migrated or deleted. The CI matrix still supplies Python 3.12 on all three runners and now checks the **installed venv** minor version in the uploaded metadata, failing on drift.

The installer also supplies a staged `pip --constraint` file from [moonshinePythonDependencies.ts](../../apps/desktop/moonshinePythonDependencies.ts), using the exact **observed** 2026-11-22 versions for 13 shared distributions and Windows-only `colorama`. It then compares the actual isolated venv package/version inventory against the allowlist, rejects new, missing, duplicate or different packages, and runs `pip check` before activating the model. The top-level SDK wheel SHA-256 check and separate eight-model-file verification remain in place. Constraints are removed from private staging before activation; the install is still transactional.

**Limitations:** version constraints and installed-version checks do **not** establish transitive Wheel SHA-256 integrity, fixed Python patch versions, immutable PyPI provenance, license or NOTICE clearance, or human-microphone acceptance. The installed snapshot is a *candidate pin set* pending three-platform native CI, not a guarantee of success on other Python versions or older machines. A proper complete multi-platform hash lock, original Wheel/license audit, and human device tests remain open release gates. No published v1.0.4 decision is implied.
