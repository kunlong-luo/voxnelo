### Wheel `License-File` coverage recheck (2026-11-23; NOT LICENSE APPROVAL)

The 2026-11-23 review found a **collector blind spot**, not a new license clearance: the earlier offline ZIP scanner recognized files mainly when the **basename** contained `LICENSE`, `NOTICE`, `COPYRIGHT` or similar. A file inside `.dist-info/licenses/` can instead be named e.g. `AUTHORS` or `Apache-2.0.txt`; the old report could omit those despite successful Wheel SHA verification. Therefore the **33/34/33 counts above are historical output from run #45133547540, not a confirmed complete set of all legal files**. Do not silently revise them or claim a real new archive pass without a newer run.

The updated [read-only original Wheel ZIP collector](../../scripts/collect-moonshine-wheel-archive-evidence.py) now inventories files in known legal/notice directories regardless of their basename, and checks the **exact declared `License-File` paths** relative to `<distribution>.dist-info/licenses/`. The [official Wheel specification](https://packaging.python.org/en/latest/specifications/binary-distribution-format/) requires that layout for core metadata version 2.4+; [core metadata](https://packaging.python.org/en/latest/specifications/core-metadata/#license-file-multiple-use) explains the `License-File` field. Output includes `declaredLicenseFiles`, `declaredLicenseArchivePaths`, `missingDeclaredLicenseFiles`, `pep639LicenseLayoutRequired` and `declaredLicenseFilesLocated`. The sanitized report and Actions log also give per-platform **ZIP-member counts** (`noticeFileCount`, `nativeBinaryCount`, `declaredLicenseFileCount`, `missingDeclaredLicenseFileCount`) to make review diffs reproducible without uploading actual license texts or binaries. Those counts measure scanning coverage only, not legal sufficiency. A missing declared file is **recorded for human investigation**, not silently treated as present; suspicious/malformed paths and duplicate declarations are rejected. Original publisher ZIP bytes remain read-only and SHA-256 checked.

For updated evidence, rerun the **scoped, read-only** [Moonshine Wheel digest / original ZIP inventory Action](https://github.com/kunlong-luo/voxnelo/actions/workflows/moonshine-wheel-digest-matrix.yml) against the **intended source SHA**, archive three OS-specific sanitized JSON inventories, and compare them to the prior report. Inspect the **actual legal text privately**, including files that are not named `LICENSE`/ `NOTICE`; review embedded ONNX Runtime, OpenBLAS, PortAudio and other native transitives and final Electron/npm components. An empty `missingDeclaredLicenseFiles` array checks declaration *presence only*: it does **not** prove completeness of all third-party notices, legal compliance, SDK/model rights, reproducible binary provenance or v1.0.4 release readiness. Model exact eight-byte upstream SHA-256 approval and direct-human microphone QA remain separately **PENDING**.

### Follow-up: bind original Wheel legal evidence to distribution identity (2026-11-24)

A source review found another narrowly scoped **collector consistency gap**: the earlier scanner validated the Wheel filename and `METADATA` `Name`/`Version` values, but did **not** establish that the ZIP member containing `METADATA` lived in the **matching top-level `{distribution}-{version}.dist-info/` directory**. A different or nested `.dist-info` root could therefore be used to associate LICENSE/NOTICE paths with the wrong distribution even when the self-reported header looked correct. This is a technical scanner finding, **not** evidence that any of the previously downloaded original Wheels were malicious.

The [read-only scanner](../../scripts/collect-moonshine-wheel-archive-evidence.py) now rejects foreign, wrong-version and nested `.dist-info` roots, while allowing equivalent normalized package-name spellings (e.g. `moonshine_voice` and `moonshine-voice`). It records `distInfoRoot` and `distInfoMatchesWheelIdentity: true` **only after checking** the archive directory and header identity. The behavior is guarded by offline regression fixtures. This follows the [Wheel distribution specification](https://packaging.python.org/en/latest/specifications/binary-distribution-format/) and does **not** interpret `METADATA` identity or a complete `License-File` inventory as legal clearance.

**Evidence scope:** the preceding real three-OS audit [#45188947162](https://github.com/kunlong-luo/voxnelo/actions/runs/45188947162) was run *before* this additional root-identity assertion; its 13/14/13 file counts, 30/31/30 declarations and 0 missing paths remain valid **observations for that exact source commit**, not proof that the new assertion has passed on those archives. **Follow-up recheck succeeded:** [read-only Wheel audit #45294831570](https://github.com/kunlong-luo/voxnelo/actions/runs/45294831570), source head `d19c5bc34b11cb054e07821d78ef22868d7cc1c1`, completed on actual Linux x64 / Windows x64 / macOS ARM64 Python 3.12 runners.
