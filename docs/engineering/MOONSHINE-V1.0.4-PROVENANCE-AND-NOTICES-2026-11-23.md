Voxnelo hashes those eight files after user-initiated download in [moonshineIntegrity.ts](../../apps/desktop/moonshineIntegrity.ts). **2/8 matching does not establish provenance.** The dated `quantized_26_07_30` files are **not** evidence for the six older/different pinned tensors. The fixed `e3181172…` commit authenticates where **the different dated table** was read, not where Voxnelo's six different legacy model tensors came from. The later `quantized_26_08_21` catalog uses `frontend.model.ort` and `frontend.weights.ort` rather than the older single `frontend.ort`, so it is not a filename-compatible drop-in for this pinned v0.0.65 runtime. Do not silently upgrade the model or rewrite existing reference hashes to make an audit pass.

The [Moonshine Hugging Face documentation](https://moonshine-voice.readthedocs.io/en/stable/models/huggingface/) says model archives are tagged by published version, but the live [official asset refs API](https://huggingface.co/api/models/moonshine-ai/moonshine-voice-assets/refs) checked **2026-11-23** exposed only `v0.1.5` (`7e08470c1127726f026f0205867c3055d602fe8c`) and `v0.1.6` (`964a20c89aea67d0aca90dd0f85d533a9a05efe2`), plus `main` (`e318117203f245fda2ca0142db6b8c057d86671c`). The [direct `v0.0.65` revision URL](https://huggingface.co/moonshine-ai/moonshine-voice-assets/tree/v0.0.65) returned **404 Invalid rev id** on that date. The published fixed tags' `FILES.tsv` lists newer dated `quantized_26_08_21` entries, **not** the exact legacy `quantized/` eight-file SHA-256 inventory. Those `FILES.tsv` records use **MD5 and CRC32C**, not SHA-256; comparing them to current SHA-256 is invalid. The immutable `main` commit's `TRANSFER_REPORT.tsv` supplies SHA-256 for `quantized_26_07_30` and still matches only two. This is **positive evidence of a current public catalog gap**, not proof no older publisher archive exists privately or in another location. A publisher-authored immutable record for the original eight files is still required. If it is unavailable, document an upstream confirmation/permission or hold the new native rollout.

**New read-only check:** `node --experimental-strip-types scripts/compare-moonshine-model-catalog.mts <trusted-local-TRANSFER_REPORT.tsv> model/medium-streaming-en/<exact-quantized-directory>`. This command checks **every exact path and SHA-256**, fails on partial/missing/malformed catalogs, and always reports `upstreamRevisionVerified:false` and `redistributionRightsApproved:false`: the caller must separately validate the file's origin, immutable revision, signed/provenance evidence (if any) and legal terms. Regression tests contain the eight publicly observed dated-table values explicitly as a **different-version comparison**, not as evidence that these are the v0.0.65 production assets. The additional opt-in command `pnpm asr:moonshine:upstream:refs` reads only the **official Hugging Face refs API** and SHA-256 text catalog at each returned exact immutable commit; it reports `v0.0.65` tag presence, exact eight-file `quantized/` matches and alternate dated-file matches, and intentionally exits nonzero on the current unresolved release evidence. It never downloads model weight binaries, changes installed models, or flags legal/model/human-mic approval. A failed network call is reported as **audit unavailable**, not falsely as “tag absent.”

### Wheel `License-File` coverage recheck (2026-11-23; NOT LICENSE APPROVAL)

The 2026-11-23 review found a **collector blind spot**, not a new license clearance: the earlier offline ZIP scanner recognized files mainly when the **basename** contained `LICENSE`, `NOTICE`, `COPYRIGHT` or similar. A file inside `.dist-info/licenses/` can instead be named e.g. `AUTHORS` or `Apache-2.0.txt`; the old report could omit those despite successful Wheel SHA verification. Therefore the **33/34/33 counts above are historical output from run #45133547540, not a confirmed complete set of all legal files**. Do not silently revise them or claim a real new archive pass without a newer run.

The updated [read-only original Wheel ZIP collector](../../scripts/collect-moonshine-wheel-archive-evidence.py) now inventories files in known legal/notice directories regardless of their basename, and checks the **exact declared `License-File` paths** relative to `<distribution>.dist-info/licenses/`. The [official Wheel specification](https://packaging.python.org/en/latest/specifications/binary-distribution-format/) requires that layout for core metadata version 2.4+; [core metadata](https://packaging.python.org/en/latest/specifications/core-metadata/#license-file-multiple-use) explains the `License-File` field. Output includes `declaredLicenseFiles`, `declaredLicenseArchivePaths`, `missingDeclaredLicenseFiles`, `pep639LicenseLayoutRequired` and `declaredLicenseFilesLocated`. The sanitized report and Actions log also give per-platform **ZIP-member counts** (`noticeFileCount`, `nativeBinaryCount`, `declaredLicenseFileCount`, `missingDeclaredLicenseFileCount`) to make review diffs reproducible without uploading actual license texts or binaries. Those counts measure scanning coverage only, not legal sufficiency. A missing declared file is **recorded for human investigation**, not silently treated as present; suspicious/malformed paths and duplicate declarations are rejected. Original publisher ZIP bytes remain read-only and SHA-256 checked.

For updated evidence, rerun the **scoped, read-only** [Moonshine Wheel digest / original ZIP inventory Action](https://github.com/kunlong-luo/voxnelo/actions/workflows/moonshine-wheel-digest-matrix.yml) against the **intended source SHA**, archive three OS-specific sanitized JSON inventories, and compare them to the prior report. Inspect the **actual legal text privately**, including files that are not named `LICENSE`/ `NOTICE`; review embedded ONNX Runtime, OpenBLAS, PortAudio and other native transitives and final Electron/npm components. An empty `missingDeclaredLicenseFiles` array checks declaration *presence only*: it does **not** prove completeness of all third-party notices, legal compliance, SDK/model rights, reproducible binary provenance or v1.0.4 release readiness. Model exact eight-byte upstream SHA-256 approval and direct-human microphone QA remain separately **PENDING**.

### Follow-up: bind original Wheel legal evidence to distribution identity (2026-11-24)

A source review found another narrowly scoped **collector consistency gap**: the earlier scanner validated the Wheel filename and `METADATA` `Name`/`Version` values, but did **not** establish that the ZIP member containing `METADATA` lived in the **matching top-level `{distribution}-{version}.dist-info/` directory**. A different or nested `.dist-info` root could therefore be used to associate LICENSE/NOTICE paths with the wrong distribution even when the self-reported header looked correct. This is a technical scanner finding, **not** evidence that any of the previously downloaded original Wheels were malicious.

The [read-only scanner](../../scripts/collect-moonshine-wheel-archive-evidence.py) now rejects foreign, wrong-version and nested `.dist-info` roots, while allowing equivalent normalized package-name spellings (e.g. `moonshine_voice` and `moonshine-voice`). It records `distInfoRoot` and `distInfoMatchesWheelIdentity: true` **only after checking** the archive directory and header identity. The behavior is guarded by offline regression fixtures. This follows the [Wheel distribution specification](https://packaging.python.org/en/latest/specifications/binary-distribution-format/) and does **not** interpret `METADATA` identity or a complete `License-File` inventory as legal clearance.

**Evidence scope:** the preceding real three-OS audit [#45188947162](https://github.com/kunlong-luo/voxnelo/actions/runs/45188947162) was run *before* this additional root-identity assertion; its 13/14/13 file counts, 30/31/30 declarations and 0 missing paths remain valid **observations for that exact source commit**, not proof that the new assertion has passed on those archives. **Follow-up recheck succeeded:** [read-only Wheel audit #45294831570](https://github.com/kunlong-luo/voxnelo/actions/runs/45294831570), source head `d19c5bc34b11cb054e07821d78ef22868d7cc1c1`, completed on actual Linux x64 / Windows x64 / macOS ARM64 Python 3.12 runners. All three jobs re-downloaded and verified the pinned original Wheels and applied the new `.dist-info` root-identity assertion. The observed inventory was unchanged: **13/14/13 Wheels, 33/34/33 indexed legal-file members, 30/31/30 declared License-File paths, and 0/0/0 missing declared paths**. These are **new technical file-association results**, not original-build attestations or license-text reviews. The model eight-byte immutable publisher reference, full legal texts, native transitive notices and human microphone acceptance are still **PENDING**.
