# Voxnelo V0.1 — Release Candidate 操作与验收手册

> 依据冻结版 `docs/Voxnelo-Product-Docs-v1.0/docs/08-测试验收与发布.md`。本手册用于生成**未签名的内部测试候选包**，不是正式公开发布授权。所有 F001–F012 P0 项必须在 `V0.1-ACCEPTANCE-MATRIX.md` 中留下真实证据。

## A. 生成三个平台的候选安装包

1. 先确认 `main` 的 CI 完整通过，且无未合并的发布修复 PR。
2. 在 GitHub 仓库 **Actions → Desktop release candidate → Run workflow**，选择 `main` 运行 `workflow_dispatch`。此流程不创建 GitHub Release 或 tag；需要跨平台安装包附件的 Draft，可在核对发布范围后使用 [独立的手动草稿工作流](GITHUB-RELEASE-DRAFT.md)。
3. 检查 Linux（`--linux deb AppImage`）、Windows（`--win nsis`）、macOS（`--mac dmg`）三个 job 均通过。
4. 下载该次 workflow 的 `voxnelo-linux-unsigned`、`voxnelo-windows-unsigned`、`voxnelo-mac-unsigned` artifacts。每个平台同时产出 `SHA256SUMS-<platform>.txt` 和 `candidate-manifest-<platform>.json`，其中记录实际安装文件 SHA-256、字节数、CI commit、run ID，并明确 `unsigned=true` / `publicReleaseApproved=false`。复核校验和与下载文件完全一致，再记录工作流地址及测试日期。
5. 工作流会检查正式候选安装包文件，而不是只验证解包文件：Linux `.deb` / `.AppImage`，Windows NSIS `.exe`，macOS UDIF `.dmg`。它们尚未签名或公证，不自动发布 GitHub Release。

**注意**：GitHub Actions 产物默认只保存 14 天；若需要长期留档，应由仓库维护者在受控位置保存 SHA-256 和适当权限的测试包。

## Linux 中文字符显示验收（新增）

如果安装后中文显示成方框、空白或乱码，先区分：
- **应用界面文字（English 正常、中文变成方框）**：一般是系统缺少 CJK 字体。Debian/Ubuntu 的新 `.deb` 已显式列出 Electron 所需系统依赖以及 `fonts-noto-cjk`。注意 electron-builder 26.15.3 曾把 `deb.depends: ["default", "fonts-noto-cjk"]` 错误写成安装包的字面 `Depends: default, fonts-noto-cjk`，导致 apt 无法找到名为 `default` 的依赖。新版本必须通过 CI 中的实际 `apt-get install` 门禁。用 `sudo apt install ./release/voxnelo_0.1.5_amd64.deb` 安装，以便 apt 自动解析字体依赖；已有安装可用 `sudo apt install fonts-noto-cjk`，然后彻底重启 Voxnelo。若仍有问题，检查 `fc-match 'sans:lang=zh-cn'`。
- **AppImage**：不经过 Debian 包管理，无法自动安装该依赖。在 Debian/Ubuntu 上手动安装 `fonts-noto-cjk`；其他发行版需使用其官方软件源提供的等效 CJK 字体。此项在系统无 CJK 字体的 AppImage 上仍需实机验证。
- **英文、窗口装饰或安装器本身也乱码**：不一定是中文字体问题，应同时收集操作系统发行版、软件包类型、安装器截图、Voxnelo 窗口截图及 `locale` 和 `fc-match` 输出，排查字符编码/字体回退或安装器界面故障，不要直接宣称字体依赖已解决全部乱码。

复测时必须分别覆盖 `.deb` 和 `.AppImage` 的中英双语、标点符号与教学句子（包括新增素材库），并保留证据。

### 无法安装时的排查步骤（Linux）

如果检查输出为 `Depends: default, fonts-noto-cjk`，**这是旧的错误安装包**，不能通过 `sudo apt` 反复重试修好。请从包含明确依赖列表和 apt 安装测试的新 `main` 重新生成候选包。


**先区分打包与安装**：`pnpm pack:linux` 仅生成 `.deb` 和 `.AppImage`；看到 `building target=deb` 不等于 apt 安装已执行。复制到聊天后显示的 `&#x20;` / `&#xA;` 是文字被 HTML 实体转义，不能当成系统安装器的实际错误。

在仓库根目录执行：

```bash
pnpm pack:linux
echo "build exit code: $?"
pnpm diagnose:linux
```

`diagnose:linux` **不会安装软件、修改依赖或要求 sudo**：它检查已生成的包、操作系统与字符编码、中文字体回退，并使用 `apt-get -s install` 模拟依赖解析。如果模拟失败，保留 **FAILED** 行和上面的 apt 错误文本。

如果打包与模拟都成功，但真正安装仍失败，再执行：

```bash
sudo apt install ./release/voxnelo_0.1.5_amd64.deb
```

请保留这条命令的**完整错误输出与退出状态**，不要只贴 Rsbuild/electron-builder 的编译日志；它们无法定位系统包管理器错误。如果系统是非 Debian/Ubuntu/Pop!_OS 系列，应使用适合发行版的安装方式。

新的 CI 会在 Ubuntu runner 上**实际用 apt 安装 `.deb`**，核对已安装的软件包、中文字体依赖和桌面启动器；候选版也有同样的安装门禁。它不能代表所有用户的本机 apt 软件源、Wayland/X11 和字体渲染均已被验证。



## C. 核心闭环验收（F003–F005）

1. 新安装、无需账号进入单句练习，播放当前句英语示范；慢速、正常与重播均有实际声音，系统无英语语音包时必须给出可理解的提示。
2. 明确授权麦克风，点击录音按钮开始，再点击**同一个按钮**停止，回听到最新一次声音；在尚未录制成功时不能显示假的可播放音频。
3. 录制三次，最后回听的必须是最后一次；播放回听时换句，旧音频必须停止；换句后不应提供上一句的回听。
4. 拒绝麦克风权限或拔掉设备仍能浏览、播放、收藏和换句，不崩溃、不误报成功。
5. 关闭重启后历史/收藏/复习标记仍存在，只有浏览的句子不会被算为已录音练习。
6. 禁用网络后仍可打开本地课程与历史。系统语音服务依赖具体平台，不能把未验证的 TTS 宣传成“所有平台离线专业录音”。

## D. 公开发布前的人工门禁

- [ ] F001–F012 逐条有平台、操作、预期、实际、截图/日志、责任人和日期的验收记录。
- [ ] `V0.1-CONTENT-REVIEW.md` 中全部 40 句的英文、中文、美式 IPA、参考音频来源和分发权由合适人员审核签署。
- [ ] 产品品牌/商标、隐私说明、问题反馈及安装/卸载/更新文档经过核对。
- [ ] 真实麦克风与离线操作在主要目标平台完成测试，安全告警与未签名限制充分披露。
- [ ] 至少 5 位目标初学者独立完成核心流程，记录阻碍及修复。
- [ ] 如默认安装包没有已验证的本地 ASR 引擎，不能宣称桌面实时听写开箱即用；不得伪造识别内容或开启未经许可的云音频上传。

只有完成这些条件，才可考虑 `v0.1.0` 的公开 Early Access 发布。候选包用于内部验收，不表示以上门禁已被解除。
