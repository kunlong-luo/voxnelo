## Exact integration under review

- Voxnelo invokes an **opt-in**, isolated local Python environment and pins `moonshine-voice==0.0.65`. The standard Linux x64 / Windows x64 / macOS 15+ ARM64 installers do **not** bundle the Python SDK, wheels or Moonshine model weights. User interaction is required before installing them.
- The English Medium Streaming **quantized** model is verified against the eight immutable file SHA-256 values in [moonshineIntegrity.ts](../../apps/desktop/moonshineIntegrity.ts); hashes establish local byte equality, not copyright provenance or third-party license compatibility.
- The user-initiated installer uses [install-moonshine-linux.mts](../../scripts/install-moonshine-linux.mts) to obtain the pinned SDK from PyPI and model from the Moonshine downloader/CDN. A separate private CI job exercises the real native runtime, PCM and packaged Electron Worker. This is not a measurement of microphone-to-subtitle latency or speech recognition accuracy.
- Because v1.0.4 installers include code that **facilitates downloading** external components, their separate licenses and provider terms must be assessed even though weights and wheels are not bundled with the Voxnelo installer.

## 2026-11-22 per-platform installed-license metadata collection (NOT approval)

The native compatibility workflow now proposes an extra **read-only evidence step** after its real opt-in SDK/model installation on Linux x64, Windows x64 and macOS 15+ ARM64. It uses `scripts/export-moonshine-license-inventory.mts` and Python's standard-library `importlib.metadata` without importing Moonshine or opening any model/audio. Each runner writes a sanitized 14-day Actions artifact `moonshine-license-<platform>.json` with installed distribution names/versions, declared SPDX license expressions/classifiers, notice/LICENSE relative paths and checksums, and native binary **relative filenames**. Export deliberately records `licenseApproved:false`, `copyrightAndRedistributionReviewed:false` and separate entries lacking license metadata; no home directory, local voice, transcript, user device ID or private installer path is included. A successful collector does **not** certify completeness or correctness of third-party license declarations.

**Audit boundary:** these artifacts can start a per-platform legal/engineering review, not replace it. They list the *installed runtime after pip resolution*, not the exact source/notice contents of all original PyPI Wheel files, dynamic-library provenance, or model asset license/redistribution terms. A reviewer still must fetch original corresponding wheels, inspect native linked libraries, notices and dependency versions/hashes, and record approval or rejection for each exact candidate before a public v1.0.4 decision. Running this CI does not itself publish or alter a Release. Do **not** change any pending evidence entry to PASS solely because a JSON artifact was uploaded.

See the [dated 2026-11-22 actual three-platform Python dependency and versioned upstream source-license inventory](MOONSHINE-DEPENDENCY-EVIDENCE-2026-11-22.md) for concrete, nonidentifying CI observations and remaining binary/notice review obligations. **This is partial evidence, not a license or publication approval.**

## Original Wheel license-file completeness check (2026-11-23)

Earlier three-platform [Wheel ZIP inventories](MOONSHINE-V1.0.4-PROVENANCE-AND-NOTICES-2026-11-23.md) stored known LICENSE/NOTICE filenames and hashes, but an audit identified that files **inside** `.dist-info/licenses/` with non-license-like basenames could be missed. The read-only scanner now covers those directories and checks `METADATA` `License-File` declarations against the corresponding ZIP members using the [Wheel distribution format specification](https://packaging.python.org/en/latest/specifications/binary-distribution-format/). Record each missing declaration as an unresolved rights-review task; an unreferenced notice file or no declarations must not be called legal clearance. The corrected three-platform original-Wheel audit **has now been rerun and inspected**: [run #45188947162](https://github.com/kunlong-luo/voxnelo/actions/runs/45188947162), source `1e3d1274fbd52d48647cff960e698ca48b09275f`. Its Linux/Windows/macOS output contains **30/31/30 declared license-file paths, 0 missing declared paths on each target**, and 33/34/33 indexed LICENSE/NOTICE members respectively. This is **technical file-presence evidence only**; original license texts, native transitive conditions, model rights and final installer notices remain **unapproved**. This check does **not** fetch legal text for publication, execute native libraries, or turn a package's SPDX label into an approval.


### Wheel `.dist-info` association safeguard (2026-11-24)

The ZIP evidence scanner has been hardened to match the `METADATA` directory to the **same normalized distribution name and version** as the original Wheel filename and its `Name`/`Version` headers. Previously, it could select a foreign `.dist-info` root. The anonymized inventory now includes the matched `distInfoRoot` and `distInfoMatchesWheelIdentity` boolean; synthetic tests cover wrong package/version, nested metadata and normalization. The [Wheel format specification](https://packaging.python.org/en/latest/specifications/binary-distribution-format/) grounds this directory rule. Prior [real Wheel audit #45188947162](https://github.com/kunlong-luo/voxnelo/actions/runs/45188947162) predates the extra assertion. The extra `.dist-info` identity safeguard **has now passed on real original Wheel archives for all three platforms** in [scoped run #45294831570](https://github.com/kunlong-luo/voxnelo/actions/runs/45294831570), PR source `d19c5bc34b11cb054e07821d78ef22868d7cc1c1` (Linux/Windows/macOS 13/14/13 pinned Wheels; 0 missing declarations on each). This proves only byte-inventory/header-directory consistency. Source-code license declarations, full NOTICE text obligations, source-to-Wheel provenance and all eight original model bytes still require a separate human decision.
