# Voxnelo 自适应工作台布局规范 (2026-10-16)

状态：响应式布局重构分支规范；该文档只约束展示布局，不修改冻结的产品需求文档。

## 设计策略：容器优先，内容优先

- **弹性外壳**：导航固定在可控范围内伸缩（`clamp(204px, 19vw, 252px)`），主内容使用 `flex-1 min-w-0`。主内容承载命名容器 `@container/workspace`，布局由**实际可用宽度**而不是整个窗口的宽度控制。
- **工作台**：内容容器不足 840px 时单栏显示练习与信息面板；从 600px 起信息面板可采用两列；工作台可用宽度达到 840px 时再出现练习主卡 + 右侧信息栏，右栏采用 `minmax(220px,28%)`。**工作台顶对齐 `items-start`，不允许右侧信息卡总高度把主练习卡拉长，导致麦克风滚到首屏以下。**
- **内容随容器缩放**：句子位于 `@container/lesson` 内，字号按 `clamp(1.75rem,7cqi,3.5rem)` 缩放；长句必须可换行。课程卡最小高度不再常量 700px，而是 `min(700px,100dvh - 120px)`，内容过多时自然纵向滚动。
- **小屏导航独立设计**：小于 640px 时桌面侧栏隐藏，提供底部五项导航，保留当前页、无障碍名称与点击行为；主内容预留底栏与安全区空间。640px 及以上使用侧栏，在紧凑宽度收起文字以保障学习区域宽度。
- **固有尺寸布局**：设置选项与收藏列表使用 `auto-fit + minmax(min(100%, X),1fr)`，不依赖视口 `xl` 断点来决定实际卡片的内部排布；搜索框可伸展/换行。
- **保留既有功能**：录音、明确结束、回听、示范音、慢速、收藏、复习、导航、语言/主题设置、真实本地统计、离线与权限处理不因布局变化而丢失；不要将非原生 Tooltip 回退成 `title`。

## 响应式验收矩阵（CSS 布局应符合下表）

| 视口（宽×高） | 预期 |
| --- | --- |
| 320×640 / 390×844 | 底部导航，练习主卡及信息卡纵向排列，不横向滚动；录音与结束操作仍可到达 |
| 640×720 | 收起文字的左侧导航；主内容单栏，卡片/语言选项可自然换行 |
| 800×610 | 左侧紧凑导航，练习主卡在前、信息区在后；页面允许纵向滚动，结束录音可操作 |
| 1160×760 | 内容宽度决定单栏或双栏，不为凑出两栏牺牲句子与按钮的可用空间 |
| 1440×900 | 主练习卡 + 右侧信息列；主卡占据剩余弹性空间、右栏约 28%（至少 220px） |
| 缩窄 Electron 窗口 / 系统字体放大 | 不截断主操作，无横向溢出；工作台自动重排，无需重新加载 |
| 键盘与屏幕阅读器 | Tab 可到达导航、录音/停止、收藏/复习；焦点状态清晰；底栏有语义导航 |
| `prefers-reduced-motion` | 禁用非必要动效，不牺牲控件可见性与操作 |

## 技术约束与核验

- 只使用 Tailwind 4 内置容器查询和 utility，不新建页面级纯 CSS 覆盖文件，也不额外引入布局运行时/JS resize listener。
- 不修改 `docs/Voxnelo-Product-Docs-v1.0` 中的冻结源文件。
- 自动化测试验证关键语义、Container Query class、导航和录音状态；**JSDOM 不渲染实际 CSS 几何**，这些测试不能作为零溢出的证据。
- 合并前仍需真实浏览器/Electron 逐项截图：320/390/640/800/1160/1440 宽度，短/长句、录音中、语言切换、设置页、收藏列表；观察无水平滚动以及可点击焦点，不以设计稿臆测实际结果。
- 验收命令：`pnpm typecheck && pnpm lint && pnpm test && pnpm ui:check && pnpm build && pnpm perf:budget`。

## 实测截图与首屏可达性补充

- GitHub Actions `ci` 在 `pnpm build` 后启动 Chromium，检查 320×640、390×844、640×720、800×610、1160×760、1440×900 六种尺寸，分别采集练习/设置/收藏界面截图，并输出 `browser-layout-evidence` artifact。使用容器查询计算后的真实几何，严禁仅匹配 Tailwind 类名。
- 主录音按钮在上述所有尺寸的**首屏可见区域**内，窄屏还不能被底部导航遮挡；正在录音时验证固定停止按钮与底栏没有碰撞。
- 长内容可以垂直滚动，但不能因右侧统计/提示列表被拉伸而把核心操作挤到首屏以下。屏幕截图必须人工复查中文字体、布局节奏、标签与截断情况。
- Electron 自定义标题栏额外占据 44px，主外壳应使用剩余的动态视口高度，避免空白滚动；浏览器测试并不替代最终的原生窗口截图验证。

## Motion V1 — 轻量交互特效规范

这一轮不引入 Motion JS runtime。复用 Tailwind CSS 4 的 `@theme inline` animation tokens，在单一设计入口定义必要的 `@keyframes`（只改变 `opacity/transform`），业务组件由 Tailwind 类控制；不创建页面级纯 CSS 覆盖文件。

| 场景 | 动效 | 行为约束 |
| --- | --- | --- |
| 页面切换（练习 / 收藏 / 历史 / 复习 / 设置） | 320ms 轻上移与淡入 | 不阻挡导航或焦点，切页立即切数据 |
| 右侧信息卡、列表项、设置卡 | 420ms 短淡入，列表不超过 280ms 错峰 | 不能使关键操作首屏不可见，也不滥用持续动画 |
| 收藏 / 复习 | 图标 250ms 轻微弹性缩放 | 只能由真实学习状态切换触发；失败状态不能伪装成功 |
| 麦克风权限申请 | 显式等待指示 | 权限期间禁用重复启动，标签必须准确 |
| 正在录音 | 细环 1.7s 平缓呼吸 + 显式文字与停止键 | 环只是**录音状态**，不得伪称音量波形、音准或评分；停止键永远可见 |
| 真正回听 | 播放中按钮才显示选中与暂停反馈 | 只取自 HTMLAudioElement 的播放状态，不模拟波形 |
| 背景氛围 | 低透明度主题色、非常慢的装饰位移 | `aria-hidden`，不拦截鼠标，不把装饰当内容或状态 |

**无障碍与性能**：所有新增循环/入场动画都在 `motion-safe` 下启用，`prefers-reduced-motion: reduce` 时 CSS 动画时间被强制最小化；保留完整图标和文案，不依赖动效传递信息。浏览器 CI 会检测普通/减少动画偏好下的 computed styles，除响应式图片外保留输出证据；继续执行当前 JS/CSS gzip 预算，避免引入运行时。

**验收重点**：切换页面可读性、键盘焦点与录音停止可达性优先于动效；浏览器截图需待 420ms 入场完成后拍摄，防止半透明状态被误判为实际设计颜色。

## Linux Electron 原生窗口集成验收（2026-10-16）

浏览器/CDP 页面测试仍保留，但不代替原生窗口测试。CI 安装 `Xvfb + Openbox + xdotool` 并直接以 `electron .` 启动**构建后的真实桌面应用**；脚本 `scripts/check-electron-window.mjs` 连接其调试页采集原生截图，所有测试操作仅存在于 CI 脚本，不在生产代码增加特殊通道。

- **协议与沙盒**：启动地址必须为 `voxnelo://app/index.html`，preload 仅提供 `platform/version/windowControls/speech`；主页面无 `require` 与 `process`。
- **真实窗口几何**：检查 1160×760、800×610、1440×900 三档尺寸，窗口标题栏为 44px、`@container/workspace` 生效、无横向溢出、无错误底部手机导航。
- **首屏操作**：核心录音麦克风及整条五按钮的标签、辅助文案必须在 800×610 和更大窗口的首屏，不能只验证麦克风本体。短高度下英文句子展示区用 `clamp(12rem, calc(100dvh - 365px), 20rem)` 弹性收缩，而非截断控制区。
- **原生 IPC**：通过正式窗口控制桥接完成最大化、还原、最小化和重新激活，不通过生产应用额外增加测试用 IPC。
- **输出**：GitHub Actions artifact `linux-electron-evidence` 包含三档截图和结构化 JSON 报告；至少人眼核对 800×610 的控制区。
- **不可冒充的覆盖范围**：Linux Xvfb 是虚拟桌面窗口测试，不等于真实 Linux 发行版任务栏图标的人工验收；**Windows 和 macOS 原生窗口、显示比例、多显示器、真实声卡/录音权限仍需独立验收**。不得宣称跨平台 Electron 已经全检。

## 桌面缩放与跨平台打包验证（2026-10-16）

- Linux/X11 原生 Electron 在正常比例以及强制 `deviceScaleFactor=1.25 / 1.5` 下分别启动构建后的应用；校验浏览器 `devicePixelRatio`、`voxnelo://app` origin、preload 桥接、自定义 44px 标题栏、容器查询生效、无横向溢出、五个录音操作首屏可见。产物分别保存在 `desktop-evidence/standard`、`dpi-125` 和 `dpi-150`。
- Windows/macOS hosted runners 执行锁定依赖的构建与 `electron-builder --dir` 无签名打包，断言原生可执行文件、`app.asar`、安装包内品牌 PNG 的存在及有效 PNG 头，macOS 额外检查 Bundle ID 和麦克风权限用途声明。
- **覆盖边界**：Windows/macOS 的打包检查不是 GUI/真实启动验收；Linux 的强制 Chromium/Electron DPR 也不能完全模拟操作系统字体无障碍放大、多显示器或显示器热插拔。桌面任务栏图标与音频硬件授权仍需要相应平台的人工复核。
- CI 中不新增生产调试 IPC，也不注入渲染器私有权限。无签名产物仅供测试，不上传用于公开分发。

## 无缝全高左侧导航与局部窗口控制条（2026-10-16）

- Electron 已设置 `frame:false`，旧版 44px 横条**不是操作系统强制要求**，而是 React `DesktopTitlebar` 放在 `shell` 之前、并将导航 `top-11` 和 `h-[calc(100dvh-44px)]` 所致。
- 新结构为 `shell (display:flex)` 下两列同级 `sidebar` + `mainArea`；导航直接 `top:0; height:100dvh`，品牌行 `pt-3`，不再有顶部 44px 留白/被标题栏跨过的问题。
- `DesktopTitlebar` 仅作为 `mainArea` 的子元素，占右侧工作区顶部 44px；删掉整行分割边框、侧边栏背景色和玻璃模糊条，视觉上与工作区背景连为一体。保留可拖动的 `window-drag` 和三个 `window-no-drag` 最小化/最大化/关闭按钮；不通过隐藏标题栏来牺牲窗口操作。
- 浏览器模式不显示 Electron 标题栏，网页版布局无变化；跨平台 Electron 仍需保留 `mac` 控件顺序与原有 Tooltip Portal。
- CI 在原生 Linux Electron 的正常 DPI、125% 和 150% 下测量 `sidebar.top≈0`、`sidebar.bottom≈window.innerHeight`、`titlebar.top≈0` 和 `titlebar.left≈sidebar.right`，同时继续检查 5 项音频操作入口首屏不截断。三种窗口尺寸生成真实截图供视觉复查。
- 未改变 Node/Electron IPC 安全边界、语音录音机制或冻结的 V1 产品文档。
