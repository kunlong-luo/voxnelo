# Voxnelo · U3 视觉还原差距与落地记录（2026-10-16）

## 结论

功能、TypeScript 与 CI 的成功不等于 UI 的视觉验收。以
`docs/u3.jpeg`、`U3-I18N-MICROINTERACTIONS.md`、
`V3-VISUAL-PRODUCTION-SPEC.md` 和最新产品决策为依据，
此前主练习区仍存在严重的视觉主次问题：

| 维度 | 旧实现的偏差 | 本次修复 |
| --- | --- | --- |
| 一级操作 | 实时听写仅有 40px 矩形小按钮，录音工具的外观与其争夺注意力 | 实时听写升级为 68–76px 圆形品牌渐变主按钮；录音/慢速/示范/停止/回听保留为次级工具 |
| 英语主句 | 桌面字体被限制在 42px，主句不够突出 | 按句子容器宽度动态扩大，目标 32–54px，长句自然换行 |
| 听写反馈 | 主按钮、字幕和隐私说明被多个边框及小字号割裂 | 一个低对比度实色/半透明子区域组合开始、停止、状态和实时字幕；不再嵌套 backdrop-filter |
| 右侧信息栏 | 10px 小字和重复边框造成碎片化 | 数字、标签、提示分别提高一档可读性；保持四张来自真实学习数据的辅助卡 |
| 主题忠实度 | 只配置 `--mic-gradient` 却未作用于用户最主要的听写按钮 | 两种主题使用相同组件的 `bg-[image:var(--mic-gradient)]`，Sunset 橙色品牌按钮、Nordic 深青按钮 |
| 可验证性 | CI 的截图测试仅要求小录音按钮 ≥40px，不检查真实听写主按钮尺寸 | Chromium 六档截图同时断言圆形实时听写按钮 ≥64px，标题字体 ≥32px，保留滚动/首屏和 Electron 验收 |

## 结构取舍

U3 是审美和信息架构参考图，而不是未经审核的功能清单。用户确认**实时听写为主要交互、录音回听为保留功能**后，核心麦克风必须体现真实听写状态，而不能为了静态图片把录音误装成实时语音识别。未配置本地识别引擎的平台仍明确显示不可用，不能出现伪字幕/伪音波。系统麦克风授权窗不能自绘取代。

目前中间主卡 + 右侧学习信息栏的响应式降级来自 `ADAPTIVE-LAYOUT-SPEC.md`；在 800×610 等极窄工作区允许右栏后置，不能为了机械强制三栏把真实操作按钮裁切。1440×900 和 1160×760 必须保持完整主练习 + 辅助栏信息架构。

## 2026-10-19 · U3 桌面首屏切句导航修正

- **复现依据**：[main CI #39196792745](https://github.com/kunlong-luo/voxnelo/actions/runs/39196792745) 的 `browser-layout-evidence` 实际截图：1440×900 主卡下缘延伸至窗口底部，左右切句按钮被截掉一部分；对照 `docs/u3.jpeg`，U3 的主要音频操作和切句控制应在首屏完整可达。1160×760 紧凑布局此前反而能完整显示切句行。
- **根因类型**：900px 高窗口下，主句文本间距、装饰波形、实时听写卡、录音次级工具区及页脚之间的纵向间距累加。不能简单隐藏波形、缩小核心听写按钮或裁剪 `overflow`，否则会牺牲 U3 层级及可访问性。
- **工程改动**：适度收紧主句焦点纵向间隔、录音控制区上下空白与切句页脚的纵向填充；**不改变字体大小、主要语音按钮、波形展示、四个工具触控尺寸或听写状态机制**，也不新增页面原生 CSS。
- **回归契约**：在 Chromium 的 1160×760、1440×900、1536×900 桌面截图中检查 `referenceFooter`、上一句/下一句按钮的实际几何边界，要求整个导航行距离视口底部至少 8px。更小的桌面窗口允许工作区滚动，但不能造成音频入口和浮动停止按钮被底栏遮挡；保留六档响应式、Nordic/Sunset 视觉验证。
- **尚欠的人工验收**：以 `docs/u3.jpeg` 对照新旧截图进行品牌/材质/留白签收，再由真实 Electron、Windows/macOS 不同系统字号与 DPI 复核。自动 CI 通过只说明几何回归，不等于完成 #55 的全量视觉验收。

## 2026-10-19 · 长句、中文、IPA 与系统缩放压力测试

- **现存风险**：此前 U3 自动化只覆盖实际初始短句，主句换行（英文长句或很长的音标）、中文翻译、多行字幕和文字放大未在同一屏同时验证。CSS flex 子元素若保留默认最小内容宽度，会出现横向挤出主卡甚至整页的风险。
- **修复**：在练习主句及 IPA/翻译容器采用现有 Tailwind 4 的 `min-w-0`、`max-w-full`、`wrap-anywhere`，英文加 `text-balance`；允许长内容换行而不是裁剪。未调整原始句子、IPA 译文、尺寸固定的主听写按钮、主题语义 token 或录音状态。
- **Chromium 自动测试**：引入仅在 CI DOM 中注入的**模拟压力文本**（英文长句、中文翻译、IPA；不会写回课程或 IndexedDB），在 1440×900、1160×760 与 125%/150% 根字号模拟下检查多行、横向溢出、三个文本块顺序、听写与录音工具上下关系、页脚可滚动到达、实际按钮大小，并保存截图。根字号模拟并不等同于真正操作系统的无障碍字体设置。
- **Linux Electron 自动测试**：原生 `voxnelo://app` 窗口分别在 devicePixelRatio 1、1.25、1.5 真实 Electron 强制缩放运行相同模拟文本压力，验证文本与交互仍可滚动到达，保存不同 DPI 截图，恢复原课程文本后继续既有录音/切句测试。**CI 使用 Xvfb + 假麦克风，不能算物理设备/真人发音验收。**
- **人工仍需核对**：不同 OS 字体度量和 CJK fallback、Native Windows/macOS 大字体、长句在英/中文语言模式的排版、两个主题的阴影/材质，以及实际课程长句的视觉质量。保留 Issue #55 OPEN，不能以压力测试截图代替人工设计审阅。

## 检验与剩余工作

- 本轮用 Tailwind 4 utility + Base UI 组件完成视觉重心调整，**不添加业务纯 CSS**。保留唯一 `design-system.css` 的语义变量、主题材料、关键帧及浏览器基础样式。
- 必须通过 TypeScript/Lint/Vitest、六档 Chromium 截图几何检查、Linux Electron 800×610/1160×760/1440×900 及 125%/150% DPI、Windows/macOS package integrity。
- 设计验收还有**需要人工**的项：用真实的 U3 参考图片与稳定状态（长短句、两主题、英语/中文、录音/听写）逐屏核对留白、按钮对称、字体渲染、系统窗口控制和滚动条。当前自动化断言无法证明像素级还原。
- 冻结的 `docs/Voxnelo-Product-Docs-v1.0/` 不改。模型及真实听写可用性继续由 Issue #45 单独跟踪。
