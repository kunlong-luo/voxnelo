# Voxnelo 双主题视觉策略与验证计划（设计提案 v0.1）

> **2026-10-15 U3 更新**：最新实施基线见 [U3 视觉、国际化和微动效规范](U3-I18N-MICROINTERACTIONS.md)。新安装默认日落柔光；手动选择的北欧偏好继续生效。本页较早的默认主题描述仅为历史记录。

**状态：设计策略待验证；北欧版已合并主分支，日落版已有独立实现原型但未发布** · 2026-10-15

## 0. 决策摘要

建议将用户提供的**柔和日落流光玻璃界面**纳入品牌设计储备，与已经定义的 **Nordic Learning 北欧纯净版**形成两种候选视觉表达。两者共享同一套 UI2 三栏信息结构、同一批 React 组件、学习逻辑与麦克风安全行为。

**当前实施基线保持 [Nordic Learning v1.0](NORDIC-LEARNING-DESIGN-SYSTEM.md)。** 是否将「日落柔光」设为默认主题、是否在 V0.1 提供一键切换，尚未决定。未经用户研究，不宣称暖玻璃风会带来更高的下载转化或次日留存。

参考资料：用户在 2026-10-15 对话中上传的暖粉/雾青日落玻璃风概念图（**尚未纳入仓库资产**）。此前的 `docs/ui2.jpeg` 是蓝青科技玻璃稿，**不是**此次新增的日落概念图，不应相互混淆。

## 1. 我们从新概念图提取什么

| 新稿观察 | 值得保留的设计理念 | 必须修正的实现/可信性问题 |
| --- | --- | --- |
| 桃粉、雾青、暖米灰低饱和背景 | 初见柔和、积极、亲和，不使用高纯度霓虹 | 背景光效不得透过正文影响文字对比度 |
| 类玻璃半透明主卡和轻描边 | 高级质感与主卡的空间分层 | 主句、按钮与学习数字必须在稳定、够对比的底色上；动效和模糊可降级 |
| 左侧五项导航、中部练习、右侧四块模块 | 完全保留 UI2 的三栏信息架构 | 窗口窄时内容按重要性自然向下排布 |
| 中央英文句 + 中文 + 低对比声波 | 一句英语是核心视觉锚点 | 波形为装饰，不得暗示麦克风音频采样或实时评分 |
| 圆形跟读键和左右操作 | 主操作突出、一眼知道如何开口 | 保留**真实**播放、慢速、录音、独立停止、回听、下一句 |
| 三色桌面圆点、日期和头像 | 轻巧的系统窗口氛围 | 不伪装不可用控件：自定义标题栏须可拖拽、可最小化/最大化/关闭；头像不得暗示已登录 |
| 右侧 `3/10`、学习建议与情景卡 | 学习情况一目了然、鼓励复练 | 数值从真实本地学习记录获取；`SpeakFeed` 不是已上线的社交动态，相关表达应使用实际课程 |
| 右侧场景缩略图和底部机器人 | 友好、有人情味的辅助插画可以成为品牌资产 | 不要牺牲按钮可达性；插画是否采用需版权、资源大小、可读性单独确认 |

## 2. 两套主题的角色（**提案**）

| 维度 | Nordic Clean · 北欧纯净 | Sunset Glow · 日落柔光玻璃 |
| --- | --- | --- |
| 产品感受 | 宁静、纸感、长期专注 | 温暖、轻盈、初见有辨识度 |
| 画布 | `#F6F7F3`、`#EAF1EB` | `#F6EEE8`、`#E7F1EE`、局部雾桃粉 `#EBC6B7` |
| 主卡片 | 白色实体卡 `#FFFFFF` | 微透暖白卡；正文承载区尽可能不透明 |
| 字色 | `#273D39` | `#28383B`，优先深色稳定可读 |
| 主按钮 | 鼠尾草绿 `#387D73` | 温暖珊瑚 `#C97970` 与青绿 `#4C9B94`，仅一处主强调 |
| 边线 | `#DEE7E0` | `rgba(255,255,255,.60)` 及深色辅助边线 |
| 光影 | 轻阴影，不发光 | 可见但克制的日落光晕，无闪烁、无持续动态泛光 |
| 开发状态 | **已通过 PR #13 合并到 main** | **已在独立原型分支开发切换器，未并入 main** |

以上日落主题颜色是**候选 Token，不是最终视觉规范**；须在真实 Electron 显示和对比度检查后调整。

实际原型结构与待测事项见 [日落柔光原型实施规范](SUNSET-GLOW-PROTOTYPE.md)。

### 默认主题的决策

- **目前**：遵循上一轮已确认的北欧纯净默认界面，不擅自修改现有 PR 的实际视觉成品。
- **候选方案**：未来版本允许用户在「设置 → 外观」中切换「北欧纯净」/「日落柔光」，不绑定登录或订阅。
- **是否日落主题作为首发默认**：需要产品负责人明确决策，以及基础可用性测试；先留为开放问题。软件首次打开时不弹主题选择干扰学习。
- **V0.1 范围控制**：若切换功能影响首发稳定性，可以只交付一个成熟主题，把多主题留到 V0.2 或更后续，不为追求视觉灵活性牺牲录音流程。

## 3. 主题切换的技术提案（未实现）

- 使用全局语义 CSS tokens，例如 `--color-bg`、`--color-surface`、`--color-ink`、`--color-accent`、`--card-border`、`--card-shadow`；共享 UI2 三栏布局、DOM、React 视图及数据接口。避免为两套主题复制 `PracticeView` 或 `SettingsView`。
- 主题根节点可使用 `data-theme="nordic"` / `data-theme="sunset"`；优先用 CSS variables 和少量修饰类，不层叠两份 20KB 的完整主题覆盖。
- 允许用户显式改变主题，持久化到**本地**偏好（目前原型使用 localStorage，仅用于外观，不与 Dexie 学习统计混用）。设置中的外观选择**原型已持久化**，其他会话级选项尚未持久化。
- 加载前应用用户选择，降低闪烁；在无数据或存储不可用时回退默认主题。始终保留 `prefers-reduced-motion`、高对比度文本、明确键盘 focus、滚动条一致性。
- Electron 自定义标题栏应随语义 Token 同步换肤，但最小化/最大化/关闭等调用和权限校验不随主题改变；macOS/Windows/Linux 保持正确真实的窗口行为。
- 设计资产需本地授权或自行创作；不要因为参考图存在可爱机器人或人物缩略图就直接把 AI 示意图中的人物当作真实课程素材。

## 4. 两种主题必须共用的体验和质量红线

1. **用户能快速找到开口跟读**：优先呈现示范 → 跟读 → 停止 → 回听，不隐藏已录音状态，错误信息能被看见。
2. **真实统计**：浏览/练习/收藏/复习从现有持久化服务读取，不展示概念图中的示意数字。
3. **音频真实**：不声称已有 VAD 自动跟读、发音纠错、实时波形、连续签到、用户社区；这些属于未来版本评估。
4. **可访问**：文本对比度以 WCAG AA 作为验收目标，通常正文至少 4.5:1；大字与图形控件至少 3:1；键盘可操作，提供清晰焦点，减少动画时无持续闪烁。
5. **响应式**：在 1440×900、1160×760 和 800×610 检查无横向溢出，紧凑窗口主要按钮和顶部紧急停录可达。
6. **隐私**：外观选择与用户行为不应默认上传服务器；学习记录和录音仍遵循本地优先。

## 5. 如何验证，而不是凭感觉确认效果

**先做任务测试，再考虑展示图吸引力。** 使用两种相同信息结构的原型，尽量只变视觉，不改变文案或功能。

- 5–8 位目标学习者进行第一轮可用性测试（探索性样本，并非统计学显著结论）：能否在不提示下找到示范播放/开始录音/结束/回听；完成率、失败原因、完成用时。
- 让学习者分别评价：主句可读、按钮可发现、观看舒适、界面信任感、愿意连续使用 10–15 分钟的主观反馈；记录选择原因，而不仅是点赞数。
- 后续如果已具备合法、明示且尊重隐私的数据采集机制，可跟踪可解释的聚合指标：启动练习率、首次完成听说闭环率、复练率、报告视觉疲劳人数。**未部署采集前不要宣称存在这些数据。**
- 宣传截图对比可作为另一个独立实验：同样的标题、价值主张和渠道下观察用户行为。高点击并不自动说明学习完成率或留存更好。
- 决策门槛：没有明显的阅读或操作障碍，且用户在“首次吸引力”和“持续专注度”两方面提供一致证据，才考虑将日落玻璃设为默认；不然保持 Nordic 默认并提供可选主题。

## 6. 下一步（按最小风险顺序）

1. 评审本提案和用户新概念图，决定是否批准日落主题及默认选择。
2. 如批准，补充日落版高保真设计稿与 Token 验收截图，确保标题栏、辅助卡、窄窗口一致。
3. 提取共享 semantic token，复用 React 页面组件，实现设置内的真实切换；不改业务模型。
4. 补主题状态持久化、跨主题录音状态、窗口按钮、键盘及尺寸测试。
5. 经真实桌面截图/体验测试后发布；更新对外宣传时只描述真实已实现的能力。
