# 05｜三大杀手锏详细规格（暂不在 V0.1 实现）

> **内部目标 V0.9，正式开放 V1.0（经验证）**。功能方案的存在不代表代码已完成、模型可用或市场首创。

## S001｜SpeakFeed：沉浸式短句流

### 核心体验

用户只看到一句当前级别合适的英语。上滑下一句，下滑上一句；收藏/历史随时可达。与短视频不同，目标不是无限停留，而是让用户找到愿意开口的一句。

### 输入

个人偏好、当前语言方向、句子难度、主题、收藏、练习记录、复习到期时间。

### 初始规则推荐

- 适度混合新句、到期复习句与偏好主题句；比例通过测试调整。
- 不连续重复相同句子，不因为跳过就给低分。
- 历史中任何句子可一键重练。
- 可以关闭自动推荐，按主题浏览。

### 容错

- 快速连续滚轮只切换一次，防意外多页。
- 音频播放/录音中切换先清理会话。
- 允许上一句/历史恢复原始句子，不丢失练习状态。

## S002｜Speak Karaoke：真实语音进度可视化

### 核心体验

用户跟读已知目标句，单词会随着用户的真实语音识别进度平滑点亮；不会固定时间自动填充。未读保持白灰，当前词黄色活动状态，稳定确认后绿色。

### 基本处理链

`麦克风 → 采样/降噪(可选) → VAD → 流式 ASR → 临时结果 → 目标句词级对齐 → 确认事件 → 高亮动画`

### 算法责任

- VAD 只能检测语音活动，不能识别具体英语词。
- ASR 给出可能词序列；临时转写可修订。
- 对齐引擎只在目标序列内合理推进，处理停顿、重复、漏词、缩写、标点和噪声。
- 高亮渲染只消费确认事件，不能因为波形跳动而填绿。
- 词级跟踪与音素级发音是否正确是不同任务。

### 防止假成功

- 只读一半句，最多点亮已稳定匹配的前半段。
- 播放系统示范音时不得把扬声器声录成用户答案。
- ASR 未确认时可以显示柔和活动态，不能直接永久绿色。
- 模型不可用时明确降级为普通录音回听，不模拟识别。

### 性能目标（探索值，非宣传承诺）

- 音量波形反馈：主观实时；工程建议优先测试约 100ms 内的响应感知。
- 稳定词级进度：目标接近 1s 内可见（需不同硬件实测）。
- 低功耗、内存与模型下载大小需实测。若达不到用户可接受的跟随体验，推迟发布。

## S003｜Smart Prompt：可开关自动接话

### 用户价值

用户忘记下一词时，App 温柔示范下一个单词，让学习者接着往下说，不强制从头读。

### 用户配置

- 主开关：**开 / 关**。关闭时不自动播提示。
- 等待时间：**3 秒 / 5 秒（建议）/ 8 秒**。
- 提示模式：仅文本提示 / 文本 + 标准音频（可根据无障碍需求调整）。
- 语速：跟随当前示范播放偏好。

### 触发条件（全部满足）

1. 当前会话处在允许用户朗读的状态。
2. 有一个高置信度确定的下一目标词/词组。
3. 已持续无有效朗读进展达到设置时长。
4. 用户当前未在说话，麦克风信号没有正在进行的语音活动。
5. 当前目标位置本轮还没有自动提示过。
6. 系统自身参考音频或提示音未在播放。

### 执行动作

当前词轻微呼吸 → 可见简短音标/中文提示 → 低干扰播放一次当前词标准音频 → 继续等待用户自己说。

### 取消与失败

- 一旦用户继续说话，取消尚未播放的提示。
- 识别进度变化，立即重新计算当前目标。
- 找不到确切待读词，不要乱提示；改为中性提示“可以慢慢来”。
- 不自动修改用户已完成进度，也不把自己的示范当成学习者发音。

## S004｜专业发音纠正（候选 V1.1+）

这是与三大特色相关但更高风险的能力：需要经过验证的发音评估模型，才允许标红某个单词或 IPA 音素。普通 ASR 的“文字匹配”不能推导“音标发对了”。不能公平评价不同合法口音时，优先不给分，而不是误判。若未来能实测可靠，可通过独立特性开关上线。

## V1.0 核心场景测试

1. 用户只说 `I want to`，后两个词保持未完成。
2. 用户说 `I want to...` 停顿 5 秒：开启智能接话时仅示范 `learn`；关闭时安静等待。
3. 用户在 4.9 秒继续说话：不得突然播放提示盖住人声。
4. 用户重复 `want`：对齐不应错误跳到后方同名词。
5. 切换短句时立刻停止旧句示范、录音会话及提示定时。
6. 用户麦克风静音或权限拒绝：保持可用后备模式，不能虚构绿色反馈。
7. AI 模型结果反复修订：活动态可变化，不引起页面剧烈闪动。
