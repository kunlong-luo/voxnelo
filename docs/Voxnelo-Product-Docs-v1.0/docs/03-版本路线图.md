# 03｜版本规划与里程碑

> 核心发布策略：**基础功能先上桌面，三大特色放到 V0.9 内测、V1.0 正式公开。** 时间是目标，不是对所有设备的确定性承诺。

| 版本                  | 目的                   | 面向用户             | 必需交付                                                 | 退出条件                             |
| --------------------- | ---------------------- | -------------------- | -------------------------------------------------------- | ------------------------------------ |
| V0.1 Early Access     | 最快验证基础口语练习   | 邀请用户、小范围公开 | 参考音频、录音回放、单句切换、历史、收藏、30–50 句       | 一次听说闭环、无严重崩溃/数据丢失    |
| V0.2 Guided Practice  | 让零基础用户更容易开口 | 小范围公开           | 中文引导、分段跟读、手动求助、待复习                     | 学习者能不查资料完成一轮跟读         |
| V0.3 Learning Edition | 改善复练和产品稳定性   | 扩展体验群           | 规则推荐、搜索、数据导出、100–200 句                     | 回访和练习数据可用于产品决策         |
| V0.9 Internal Lab     | 验证技术杀手锏         | 开发/受邀内测        | SpeakFeed、Speak Karaoke、Smart Prompt 原型与定量测评    | 低延迟、误识别、安全性达到预设阈值   |
| V1.0 Public Launch    | 正式推出特色体验       | 公开市场             | 三大特色（仅发布验证达标部分）、桌面打包、文档、用户支持 | 真实初学者测试通过、平台质量闸门通过 |
| V1.1+                 | 更深入的纠音           | 现有用户             | 有证据的词/音素评估、薄弱发音训练                        | 误判经过人工评估，口音公平性达标     |
| V2.x                  | 移动端与双向语言       | 全球用户             | Android、iOS、普通话课程、独立语音识别适配               | 手机端性能、权限、商店审核和内容达标 |

## 分阶段决策门槛

### Gate A — 启动 V0.1

- 确认工作名称的对外使用边界，正式上线前必须完成商标与域名核验。
- 可合法使用的首批参考音频素材已经准备。
- 定义一个桌面操作系统作为首发主要验收目标，其余平台在具备设备/CI 后逐项验收。

### Gate B — 对外发布 V0.1

- “听示范 → 录音 → 回听 → 换句 → 历史”经过真实设备验证。
- 拒绝授权麦克风时应用可用；历史持久化正确。
- 至少 5 位英语初学者完成端到端任务，核心阻碍项已修复。
- README 写清楚“暂不提供自动发音纠正”。

### Gate C — 投资 V0.9

- 用户确实愿意跟读而不是只浏览。
- 有复练行为，且反馈表明用户希望更及时的朗读进度与帮助。
- 真实流式 ASR 的技术可行性已经用短句、停顿、多种口音和低配设备验证。

### Gate D — 发布 V1.0

- SpeakFeed 手势稳定，桌面滚轮不误触发。
- Speak Karaoke 高亮不欺骗用户：不会仅按时间填色，不会在半句时标全绿。
- Smart Prompt 误触发率可接受，可以彻底关闭。
- 如发音纠错无法通过测试，暂不公开红色“错音”效果；不阻止已合格的三大核心体验上线。

## 桌面与移动端时序

**V0.1 桌面优先**，共享 React 学习内核，未来可增加 Web 入口。移动端是明确产品方向，但 Android/iOS 发布不应阻塞桌面 Early Access。移动端并非简单封装安装包，需要对麦克风录音、离线模型、手势与后台权限单独开发和测试。

## 版本规则

- 新需求必须标注版本、价值、成本和风险。
- P2 的“想法”不能悄悄加入 V0.1 P0。
- 正式用户可用版本只声明已实现并测试的功能。
- 重要功能可以通过特性开关供内部测试，但不能在对外宣传中暗示已开放。
