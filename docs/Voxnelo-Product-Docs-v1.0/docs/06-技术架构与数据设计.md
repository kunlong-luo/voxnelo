# 06｜桌面优先技术架构与数据设计

## 1. 技术原则

技术选型服务产品，不追求框架名字越新越好。**桌面端优先、共享 React UI、核心逻辑可在 Web/移动端复用、未来语音引擎可替换。** 首发无需服务端、登录系统和大模型。

### 建议技术栈（开发启动时锁定兼容版本）

| 层次      | 推荐                                         | 备注                                                      |
| --------- | -------------------------------------------- | --------------------------------------------------------- |
| UI        | React 19.x + TypeScript strict               | 使用稳定兼容版本                                          |
| 构建      | Rsbuild/Rspack                               | 若 Electron 集成插件存在兼容性问题，可分离主/渲染进程构建 |
| 桌面      | Electron                                     | Windows、macOS、Linux                                     |
| UI / 样式 | Tailwind CSS 4 + 按需 shadcn/ui              | 避免过度组件化                                            |
| 状态      | Zustand + 显式学习/录音状态机                | 避免录音、音频和换句竞态                                  |
| 存储      | IndexedDB / Dexie                            | 用户本地历史与收藏                                        |
| 音频      | MediaDevices / MediaRecorder / Web Audio API | 实机检查权限与格式差异                                    |
| 动效      | Motion 或 CSS transitions                    | 第一版轻量，未来扩展 Karaoke                              |
| 校验      | Zod                                          | 内容、存档与 IPC                                          |
| 测试      | Vitest + Playwright                          | 纯逻辑 / 真实交互                                         |
| 发布      | electron-builder + GitHub Actions            | 每系统需独立构建验证                                      |
| Monorepo  | pnpm workspace                               | 避免首发时抽出过多空包                                    |

> 具体“2026 最新”小版本必须在创建工程时核对发布说明与兼容矩阵；不强行捆绑尚未验证的版本号。

## 2. 推荐目录结构

```text
voxnelo/
├── apps/
│   ├── desktop/                # Electron main, preload, 安全守卫
│   └── web/                    # 渲染入口（src：壳/视图/hook）
├── packages/
│   ├── audio/                  # 播放与录音端口（@voxnelo/audio）
│   ├── content/                # 语言方向、句子、审核后的素材（@voxnelo/content）
│   ├── core/                   # 推荐规则、共享常量（@voxnelo/core）
│   ├── learning/               # 学习应用服务门面，UI 唯一入口（@voxnelo/learning）
│   ├── storage/                # 存储接口及迁移（@voxnelo/storage）
│   └── speech/                 # V0.9 ASR 适配器占位，暂缓实现（目录暂不创建）
├── assets/audio/               # 已授权参考音频（暂缓，见 ADR-0001）
├── docs/
├── tests/
└── .github/workflows/
```

包之间经 `@voxnelo/*` barrel 互相引用，禁止深路径相对引用（ESLint 门禁）；
各包 `package.json` 声明 `name@version`，`learning` 经 `workspace:*` 依赖其余四包。

V0.1 如果还没有多端消费者，可先将模块置于 apps/desktop/src/modules，保留清晰接口，避免早期拆成大量独立 npm 包。
（注：实际已按 packages 拆分并以门面收口，见 ADR-0003。）

## 3. 模块边界

- **ContentRepository**：提供按语言/难度/主题筛选的高质量短句，禁止 UI 写死课程。
- **PracticeSession**：控制当前句、音频播放、录音、回听、切句事件。
- **AudioPort**：音频播放、录音和权限查询；后续平台独立适配。
- **ProgressRepository**：区分 viewed / listened / practiced / completed / selfMarkedMastered。
- **ReviewService**：计算到期复习；第一版规则可很简单。
- **SpeechProvider（未来）**：统一流式 ASR 事件输出；不存在时软件基础功能不受影响。
- **KaraokeAligner（未来）**：独立词级对齐算法，不直接依赖 React 组件。
- **SmartPromptScheduler（未来）**：会话/语音活动/位置/开关全部满足后才提示。

## 4. 核心数据表/对象（概念）

### Sentence

`id, sourceLanguage, targetLanguage, text, translation, ipa?, pinyin?, difficulty, topic, tags[], audioAsset, segments[], contentVersion`

### UserSentenceProgress

`sentenceId, firstSeenAt, lastSeenAt, lastListenedAt, lastPracticedAt, listenCount, speakingAttemptCount, userMarkedStatus, reviewDueAt`

### FeedHistory

`id, sentenceId, viewedAt, entrySource, sessionId`

### Favorite

`sentenceId, createdAt`

### Settings

`interfaceLanguage, learningDirection, playbackSpeed, showTranscription, smartPromptEnabled, smartPromptDelaySeconds, theme, reduceMotionPreference`

- `smartPromptEnabled` 与 `smartPromptDelaySeconds` 提前预留，但 V0.1 不展示无效开关。
- 学习方向作为用户档案的一部分，英语与普通话数据不混用。

## 5. 学习状态设计

明确区分：

- **seen**：看过句子；
- **listened**：听过示范音频；
- **attempted**：实际开始过跟读录音；
- **completed**：完成本版本要求的学习流程；
- **masteredSelfReported**：用户自评熟悉；
- **assessedPronunciation**：未来真正经可靠模型评估得到的结果，不能用前五项代替。

## 6. 状态机与竞态处理

V0.1 最小状态：`idle → playingReference → readyToRecord → recording → playbackAvailable → idle`，并处理 `paused`、`error` 和 `sentenceChanging`。

- 每次播放/录音都关联会话 ID，切句后旧事件必须失效。
- 设备权限被撤销时中止录音、提示并恢复稳定 UI。
- 必须拦截同一音频多次同时播放。
- 未来 V0.9 再新增 `asrInterim / asrStable / awaitingPrompt / prompting`，不把这些空状态强塞进 V0.1。

## 7. 参考音频和隐私

- 参考音频必须能合法分发；首版关键句不依赖在线 TTS。
- 用户跟读录音默认临时存储，切句或关闭应用后按策略清理。
- 本地历史不包含原始麦克风 PCM，除非未来用户明确要求保存。
- Electron：`contextIsolation=true`、沙盒、受限 IPC、对消息类型/字段校验。
- 本地和云端识别须分别告知；用户音频未经授权不得上传。
- 未来离线模型须核查模型许可证、文件尺寸、CPU/RAM 与更新机制。

## 8. 双向语言与移动端适配预留

英语教学：IPA、单词重音、英语声学模型与英语课程。

普通话教学：拼音、声调/变调、汉字/词组切分、中文语音模型与专门课程。

语音接口建议将 `languageTag`, `readingUnits`, `phoneticNotationType` 作为显式参数，避免所有逻辑写死 `en-US`。但首版只实现 `zh-CN 界面 → en-US 学习`。

Android/iOS 后续评估 Capacitor 或 React Native；共享业务逻辑可行，但音频和语音原生能力需独立做适配与测试。
