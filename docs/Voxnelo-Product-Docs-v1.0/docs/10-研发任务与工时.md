# 10｜研发拆解、工时与资源估算

**估算口径**：1 名熟悉 React/TypeScript 的开发者，有 AI 编码助手；工时包含主要开发与基本测试。若需要真正可上线的跨平台发行、内容制作和复杂模型验证，工时显著增加。以下是规划范围，不是工期承诺。

## 1. V0.1 建议开发任务

| 编号     | 任务                                        |   预计工时 | 依赖                         |
| -------- | ------------------------------------------- | ---------: | ---------------------------- |
| T01      | 项目初始化、质量脚本、Electron main/preload |       5–9h | 无                           |
| T02      | 桌面单句页面、布局、基础微动效              |       5–8h | T01                          |
| T03      | 内容 JSON、校验、首批音频映射               |       5–8h | T01、可授权音频              |
| T04      | 英语示范播放、慢速/重播                     |       4–7h | T03                          |

不要误把普通 ASR 接通 1 小时视为“高质量实时跟读完成”；模型评估与多设备调试占比很高。

## 3. 最快发布的任务顺序

1. 锁定首发系统及音频资源授权。
2. 初始化工程，先让一条句子有正确示范音频。
3. 完成真实麦克风录音回听。
4. 加入切句、收藏、历史；所有状态可恢复。
5. 完成 30–50 句内容质检。
6. 自动化测试和一个系统的真实设备验收。
7. 小范围对外发布 Early Access，收集卡点和回访。

### 推荐首轮迭代

**第一个里程碑**：一条短句完整流程；**第二个里程碑**：30–50 句内容 + 历史收藏；**第三个里程碑**：安装包与小范围实测。

## 4. 依赖与风险缓冲

- 麦克风权限/录音格式：不同 OS 行为差异，不承诺无需调试。
- 英文参考音频：版权和语音准确性可能比 UI 工作量更关键。
- 品牌：未核验前使用开发代号与占位 Logo，避免大量返工。
- V0.9：本地 ASR 许可证、模型体积、CPU 实时性、临时转写修订是主要风险。
- 用户体验：零基础用户的误触、焦虑、无法跟读，需要真人验证。
