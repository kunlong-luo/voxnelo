## Per-platform, per-exact-build acceptance checklist

Every platform needs a dated, privacy-safe record tied to the **tested installer SHA-256**, source commit and model version/hashes; neither a file name nor `package.json` version alone establishes the tested build.

1. **Provenance and installation:** OS version/architecture (nonidentifying), CPU/RAM tier, mic category, clean install and in-place upgrade, local user data preserved, Python SDK install only after opt-in, SDK/model absent from ordinary installer.
2. **Real input, explicit consent:** A human speaks directly into a **physical microphone** on the tested device. Verify permission grant, denial, device disconnect/reconnect and disabled/offline/error states. A synthetic waveform, system TTS, loopback, or another device playing audio does **not** meet this human-microphone gate; those may be supplemental stress cases, labeled separately.
3. **Accuracy:** At least 20 distinct, consented human-spoken English reference sentences overall; at least 10 actual human-microphone trials in **quiet** and 10 in **background noise** for each target OS, recording local canonical reference transcript and hypothesis privately. Report aggregate weighted `WER = (substitutions + deletions + insertions) / reference words`, sentence count, word count, normalizer and per-scenario WER. No invented scores, zero-word denominators or claim that upstream benchmarks are Voxnelo outcomes. Track optional accent groups only with consent and adequate privacy safeguards.
4. **Interactive latency and reliability:** Measure live microphone-to-first-visible-interim and end-of-speech-to-final-visible-subtitle using the actual application **for every attempted human-microphone sentence in both conditions** (minimum **20 samples for each latency metric per OS** when there are 10 quiet + 10 noisy trials). Record failures/no interim/final subtitle as failures in the private observations, never silently discard them or publish percentiles calculated from only the easy trials. Measure CPU/RAM and 10-minute uninterrupted sessions; test Stop/restart, changing sentences, error recovery and no stale subtitle bleed. Offline WAV batch RTF or callback time is not a substitute.
5. **User experience:** Cover the applicable F001–F012 learning flow, keyboard/zoom/accessibility, microphone privacy, uninstall/reinstall and saved progress. See [frozen acceptance matrix](../engineering/V0.1-ACCEPTANCE-MATRIX.md). These are separate from the optional ASR quality gate.

## Optional private evidence-intake self-check (2026-11-23; no acceptance)

This read-only tool helps a maintainer detect **missing fields and inconsistent arithmetic** in an independently collected v1.0.4 direct-human-microphone summary, before handing it to a human reviewer. The [pending-only JSON template](v1.0.4-physical-mic-evidence.example.json) contains **no recordings, reference transcripts, test identities or actual measured results**. Copy it to a private location outside the repo and fill only from dated real-device observations. The example itself intentionally fails the checker.

```sh
pnpm asr:mic:evidence:audit /private/location/v1.0.4-physical-mic-summary.json
```

**Schema 2** is required (schema 1 records must be migrated manually using the blank template). The summary requires the **exact source commit** and **installer SHA-256** for each supported Linux x64 / Windows x64 / macOS 15+ ARM64 target, actual CPU architecture and Python **3.12.x** ABI, installed `moonshine-voice==0.0.65`, the exact platform-specific **SDK Wheel SHA-256** from the [pinned Python 3.12 inventory](../engineering/moonshine-python312-wheel-digests-2026-11-23.json), and **all eight locally measured model-file SHA-256 values** matching [the candidate's pinned bytes](../../apps/desktop/moonshineIntegrity.ts). Do not copy these expected hashes into an observed-result field without actually hashing the local installed bytes. Matching the candidate pins validates self-reported identity only; **it cannot resolve the missing publisher-authored immutable model manifest or legal/NOTICE approval**.

Also required: anonymous evidence tokens, direct human speech into a real physical mic with consent, at least **20 distinct consented reference sentences overall**, **10 quiet and 10 noisy real trials per OS**, WER numerator components and reference-word counts, **at least quiet.trials + noisy.trials latency observations for each of the two visible-UI metrics per OS**, a valid test calendar date that is not in the future (allowing the next UTC date for local timezone differences), a ten-minute session, permissions/disconnect/restart, upgrade data preservation, and offline/privacy observations. The tool computes WER from integer edit counts; it does not apply an invented acceptance threshold. Store raw references, exact hypotheses, audio and identifying metadata only in an approved private evidence store. Never commit the filled JSON, device IDs, host paths, recordings or source agreements.

The command runs **locally, without network or uploads**, and reports validation blockers for incomplete records. The input is self-reported: timestamps, microphone claims and consent must still be substantiated in privately retained original observations. Missing initial/final captions, app crashes or unmeasured trials cannot be hidden by a low sample count. If the summary cannot provide both latency measurements for all required human trials, retain that outcome as an open defect and leave the intake **INCOMPLETE** instead of inventing a number. It makes no judgement about the truth of self-reported human tests, installed binary provenance, model licensing, UI accessibility, ownership or public distribution. Even when it prints `STRUCTURE ONLY`, it always returns `releaseApproved: false` and `reviewRequired: true`; a qualified human must independently examine the **underlying** evidence and record an explicit decision. Synthetic *unit-test fixtures* demonstrate checker behavior only, not real microphone evidence. This checker is **not wired into automatic publication or release workflows**.
