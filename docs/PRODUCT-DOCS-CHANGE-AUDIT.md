# Voxnelo V1.0 产品文档变更审计（2026-10-15）

## 审计依据

对照先前交付的 `Voxnelo_完整产品文档包_v1.0.zip` 中的 Git blob SHA-1，与当前主分支 `docs/Voxnelo-Product-Docs-v1.0/`。原版共有 12 份 Markdown（README + 01–11）。GitHub 中 11 份 Markdown 的字节内容不同，唯独 `05-杀手锏功能规格.md` 未改变；Word（DOCX）、PDF 以及旧校验清单内容未改变。

**不能因此推导 11 份文件发生了同等程度的产品需求变更**：这些变化包括 Prettier 排版与补写实施说明。产品核心范围未发生实质漂移。

## 审计判断

| 项目 | 判断 | 原因/处置 |
| --- | --- | --- |
| 桌面优先、移动端与普通话长期扩展 | 保持 | 规划未被改变 |
| V0.1 基础跟读、V0.9 三大特色内测、V1.0 正式公开 | 保持 | `02`/`03`/`05` 等文件一致 |
| 音素级纠错不保证在 V1.0 发布 | 保持 | 需要专门评估 |
| `06`：从概念目录改为实际 workspace + learning 门面 | 合理，但属于实施说明 | 与源码和 ADR-0003 相符；不应偷偷宣称原冻结 PDF 已更新 |
| `07`：36 句规划种子改为当前 40 句实际清单 | 合理，但需内容审校 | `packages/content/sentences.ts` 为当前实际数据；不代表通过专业内容验收 |
| `README`：仍称整个包 Product Baseline 1.0 冻结 | **版本管理不严谨，已标注** | Markdown 已与原始 PDF/DOCX 分叉；未来另发 1.1 实施修订版 |
| `CHECKSUMS.txt` 仍是原始 SHA-256 | **不合理，已归档** | 不能继续以旧校验单验当前 Markdown，见新 README 说明 |

## 规则

1. 原始 DOCX/PDF 与旧校验清单保留作为历史基线，不伪造一致性。
2. 冻结后的功能决策变更，应单独写 ADR/决策日志并标注目标版本；实施进度写 `docs/12-工程实施与交付边界.md` 或 CHANGELOG。
3. 下一次正式整理文档时单独出 `v1.1`（或修订版）目录，并同时重新生成 Markdown、DOCX、PDF、对应 SHA-256 校验清单。**不要再在仍称 V1.0 冻结基线的文件上静默修改。**
4. V0.1 未经完整实机验收，禁止将参考 TTS 描述为专业标准音频，或将录音尝试称为掌握/发音正确。

## 未修改的产品策略

- 中文零基础学英语；未来外国用户学普通话。
- 免费、本地优先、无需强制注册。
- SpeakFeed、Speak Karaoke、Smart Prompt 均不提前混入 V0.1。
- AI/发音识别的承诺必须以实际可用且经过测试的能力为依据。
